# 검색 결과·링크 미리보기에 쓰이는 한 줄 소개
description: "왜 만드는지, 어떻게 동작하는지를 먼저 묻는 개발자"
---

고민하고 문제를 탐구하는 것을 좋아하는, 호기심 많은 개발자입니다. 최근에는 AI 작업이 많아지면서 인프라를 안정적으로 운영하는 일에 관심이 많습니다.

AI가 내놓은 결과를 사용자가 믿고 쓸 수 있도록 설계해 왔습니다. 복약 안내 서비스 Pilltip에서는 LLM이 바로 답하지 않고 공공데이터와 DUR 결과를 먼저 조회해 근거와 함께 답하는 RAG 구조를 만들었고, YOLOv8로 알약 인식 모델을 학습했습니다. 지식관리 서비스 Fruition에서는 흩어진 문서를 LLM이 위키로 정리하되, 항목마다 원문 근거를 연결하고 AI 작업을 위험도에 따라 자동 실행·사후 검토·사전 승인으로 나눠 언제든 되돌릴 수 있게 했습니다.

요청이 몰려도 버티면서 비용은 아끼는 인프라를 만듭니다. AWS EKS 인프라를 Terraform으로 구성해 멈추면 안 되는 인증 DB와 Redis는 이중화하고, 사용하지 않을 때는 노드를 0대로 줄였다가 접속하면 다시 기동하는 절전 기능을 만들었습니다. AI 요청 폭주 상황을 k6로 비교해 모놀리스에서 약 10초까지 늘던 인증 응답이 MSA에서는 7ms로 유지되는 것을 확인하고 전환을 결정했고, 수강신청 상황을 재현해 초당 2,000건 부하에서 실패율을 20.79%에서 0%까지 낮췄습니다.

AI를 팀의 개발 방식에도 적극적으로 활용합니다. 팀 공통 AI 개발 규칙과 공용 스킬, GitHub Actions OIDC 기반 자동 배포 파이프라인을 만들어 세 명이 같은 기준으로 개발하고 배포하게 했습니다. 오픈소스 rhwp에 기여할 때도 AI로 코드 흐름을 빠르게 파악한 뒤 테스트로 직접 검증해 PR 4건을 반영했습니다.

- 컨퍼런스 및 외부 네트워킹을 통해 기술적 시야를 넓히고, 여러 오픈소스를 살펴보며 새로운 기술을 꾸준히 학습합니다.
- 새로 배운 지식은 기술적인 내용이 아니더라도 팀과 적극적으로 공유하며 함께 성장하고자 합니다.
- 팀 프로젝트에서 항상 상대를 존중하는 태도로 프로젝트를 진행합니다.
