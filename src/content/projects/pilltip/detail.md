## 해결하려던 문제

처방받은 약을 함께 먹어도 안전한지는 지금도 의사나 약사가 직접 확인하는 방법에 기대고 있습니다.\
여러 병원에서 받은 처방전끼리는 서로 검증하기 어렵고, 약 봉투나 종이 처방전에 적힌 정보만으로는 사용자가 주의사항을 이해하기도 쉽지 않습니다.

고령화가 진행되면서 이 문제는 더 커지고 있습니다.\
고령층의 약 82.4%가 5종 이상의 약을 복용하지만, 정작 안전한 의약 정보를 스스로 얻기는 어렵습니다.\
그래서 사용자의 건강 상태와 복약 이력을 바탕으로 약의 안전성을 직접 확인하고 관리할 수 있는 서비스를 만들고자 했습니다.

## 내가 맡은 부분

- **인프라 운영**: 연구실 서버를 학교 밖에서 접속할 수 있게 구성하고, HTTPS 적용/Docker 배포/장애 대응까지 약 8개월 동안 직접 운영했습니다.
- **백엔드/데이터**: 카카오 소셜 로그인과 JWT 인증(토큰 재발급, 회원 탈퇴, 인증 없이 열어 둘 경로 설정 포함)을 구현하고, MySQL 스키마를 설계하고 개인정보와 처방, 문진 데이터에 AES-GCM 암호화를 적용했습니다.\
  DUR 서비스에 활용할 수 있도록 여러 곳에 흩어진 식약처/심평원 공공데이터(e약은요, DUR 품목정보, 성분별 1일 최대투여량 등)를 재정비했습니다.\
  데이터를 내려받아 정제하고, 약품/성분/건강기능식품을 하나의 기준으로 묶어 병용 금기와 대상별 주의사항(임부/연령/노인/수유부/투여 기간/과량) 테이블로 설계했습니다.
- **알약 인식**: AI-Hub 경구약제 데이터로 한 장의 사진에서 여러 알약을 찾아내는 YOLOv8 모델을 학습했습니다.
- **웹 프론트엔드**: 앱에 입력된 사용자 정보를 병원에 빠르게 전달하는 병원용 웹 문진표를 Next.js/TypeScript로 개발했습니다.

## 문제 해결과 결과

### 연구실 서버로 서비스 운영

연구실에서 지원받은 서버 한 대로 서비스 운영과 모델 학습을 모두 진행했습니다.\
학교 내부망 안에 있는 서버를 포트포워딩과 Nginx 리버스 프록시로 외부에 열어, 앱과 병원용 웹의 요청이 포트 하나로 들어와 서버 안의 알맞은 서비스로 전달되도록 구성했습니다.\
ZeroSSL 인증서로 HTTPS를 적용하고 도메인을 연결했으며, 요청 로그로 장애 원인을 추적하면서 약 8개월 동안 운영했습니다.

### 서버 용량보다 큰 학습 데이터 처리

운영 공간을 빼고 남은 1TB 안에서 AI-Hub 경구약제 데이터를 묶음 단위로 나눠 받아 YOLOv8 모델을 점진적으로 학습했습니다.\
새 묶음마다 이전 가중치를 이어받고 이전 이미지 10%를 섞어 학습했으며, 정답률이 90%를 넘은 경우에만 다음 묶음으로 넘어갔습니다.\
여러 알약이 함께 찍힌 고화질 이미지로 검증한 최종 정답률은 **92%**였습니다.

### DUR 검사를 위한 공공데이터 재정비

금기 종류마다 따로 제공되는 DUR 공공데이터를 내려받아 정제하고, 두 대상 사이의 병용 금기는 관계 테이블 하나로, 한 대상의 조건별 주의사항(임부/연령/노인/수유부/투여 기간/과량)은 주의사항 테이블 하나로 묶었습니다.\
금기 종류가 늘어나도 조회할 테이블 수는 그대로였고, 약품과 건강기능식품도 같은 방식으로 검사할 수 있게 됐습니다.

### 운영 중인 서비스의 민감정보 보호

민감정보를 사용자 테이블에서 별도 테이블로 분리하고, 실명/주소/로그인 ID/소셜 ID/복약/알러지 정보 등을 AES-GCM으로 암호화했습니다.\
JPA 컨버터로 저장할 때 암호화하고 읽을 때 복호화되게 했고, 일반 로그인과 소셜 로그인은 저장된 값을 복호화해 비교하도록 바꿨습니다.\
서버 시작 시 기존 데이터를 자동으로 암호화하던 마이그레이션 코드가 오류를 일으켜 제거하고, 민감정보 처리 로직과 암호화 로직을 다시 맞췄습니다.

QR 코드로 연 문진표는 3분이 지나면 만료되고 병원 웹 화면도 그 시각에 자동으로 닫히게 했습니다.\
복용 중인 약이나 민감정보를 바꾸거나 지웠을 때 문진표에 반영되지 않던 문제도 고쳐, 두 정보가 항상 같은 상태를 유지하도록 했습니다.

## 서비스 구성과 기능

![Pilltip 시스템 아키텍처](/img/pilltip/architecture.webp)

사용자는 Android 앱으로, 병원은 Next.js로 만든 웹으로 Pilltip을 이용합니다.\
두 곳에서 보낸 요청은 모두 Nginx를 거쳐 Spring Boot 서버로 전달되고, 서버와 저장소는 Docker 컨테이너로 띄워 운영했습니다.

MySQL은 사용자 정보와 약 데이터의 정합성을 지키기 위해 기본 저장소로 사용했습니다.\
약품 검색은 이름 일부만 입력해도 빠르게 찾고 자동완성할 수 있도록 Elasticsearch를 썼습니다.\
DUR 검사는 약을 검색하거나 등록할 때마다 실행되기 때문에, 약물 간 관계를 메모리에서 바로 꺼내 쓸 수 있도록 Redis에 미리 올려 두었습니다.\
챗봇은 RAG를 통해 공공데이터에 근거한 올바른 답을 찾을 수 있도록, 벡터 DB인 Weaviate에서 질문과 비슷한 자료를 검색합니다.\
건강 정보처럼 민감한 데이터는 AES-GCM을 통해 암호화하고 비식별화해 보관했습니다.

- **약품/건강기능식품 검색**: 이름/제조사/성분으로 검색하고 자동완성을 제공합니다.\
  검색 결과에는 사용자에게 해당하는 임산부/병용/노인/연령 주의 태그가 함께 표시됩니다.\
  상세 화면에서는 GPT-4o mini가 사용자 상황에 맞춘 복약 안내를 쉬운 말로 보여 줍니다.
- **사진으로 약 찾기**: 알약 사진을 올리면 YOLOv8 모델이 알약을 인식하고, 인식한 약의 정보를 바로 검색합니다.
- **개인 맞춤 DUR**: 복용 중인 약/건강기능식품과 건강 정보를 바탕으로 병용 금기, 대상별 주의사항, 효능군 중복을 검사합니다.\
  충돌이 있으면 왜 위험한지 GPT-4o mini가 쉬운 말로 설명합니다.
- **AI 챗봇**: 질문에 따라 DUR 확인, 제품 추천, 섭취량 안내 도구를 골라 실행하는 에이전트 구조입니다.\
  제품은 DUR 검사를 통과한 것만 추천하고, 정보가 부족하면 사용자에게 다시 묻습니다. 답변은 스트리밍으로 전달됩니다.
- **복약 관리/알림**: 복용 중인 약을 등록하면 FCM으로 복약 알림을 보내고, '먹었어요'를 누르면 기록합니다.\
  달력과 주간 화면에서 복약 완료율을 확인할 수 있습니다.
- **가족/친구 관리**: 초대 링크로 가족이나 친구를 연결해 서로의 복약 기록을 확인하고, 약을 먹지 않은 사람에게 알림을 보낼 수 있습니다.\
  만 14세 미만 자녀 계정으로 전환해 대신 관리할 수도 있습니다.
- **디지털 문진**: 개인정보 제공 동의를 받은 뒤 병원 QR 코드를 스캔해 문진표를 병원 웹에 제출합니다.\
  병원에서 관리하며 일정 시간이 지나면 자동 삭제됩니다.
- **로그인**: 아이디/비밀번호 로그인과 카카오 소셜 로그인을 지원합니다.

한정된 서버 자원 안에서 서비스를 직접 운영하고, 흩어진 공공데이터를 DUR에 쓸 수 있게 다듬고, 알약 인식 모델을 학습시킨 노력이 모여 실제로 동작하는 서비스를 완성할 수 있었습니다.\
그 결과 졸업과제 금상을 비롯해 부산 데이터 위크 최우수상, L:AUNCH 장려상, SW중심대학 디지털 경진대회 후원기업상을 받으며 서비스의 필요성과 완성도를 인정받았습니다.
