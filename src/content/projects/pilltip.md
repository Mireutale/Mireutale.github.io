## 왜 만들었나

고령층의 82.4%가 5종 이상 약을 복용하고, 환자 안전사고의 절반이 약물 사고인데 처방전 간 상호 검증은 여전히 사람 손에 맡겨져 있습니다. "왜 약 봉투는 종이인가"에서 출발해 사용자가 자기 복약 데이터의 주도권을 갖는 서비스를 기획했습니다.

## 아키텍처

![Pilltip 시스템 아키텍처](/img/pilltip/architecture.png)

Android 앱과 병원용 Next.js 웹이 Nginx(HTTPS/TLS) 뒤의 Spring Boot 서버로 RESTful API 호출. 서버는 Elasticsearch(약품 검색·자동 완성), Redis(DUR 매핑·태깅), Weaviate(자연어 질의 임베딩·Top-K 검색), MySQL(사용자·약 정보, 암호화·비식별화 저장)을 Docker로 묶어 운영. GPT-4o mini가 구어체 약 안내와 DUR 상충 비교를 생성하고, FCM으로 복약 알림 전송.

## 주요 기능

- **개인 맞춤형 DUR**: 기존 서비스는 같은 약품 데이터를 안내만 했지만, Pilltip은 사용자의 건강 정보·복약 이력을 바탕으로 "복약해도 무방" / "의사 상담 필요"를 판정하고 의학 용어를 일상 언어로 풀어 설명.
- **약품 검색 + 위험 태그**: 검색 결과마다 약품 성분과 사용자 건강 정보를 대조해 DUR 감지·비감지 태그를 표시. 임산부·병용·노약자·연령 주의를 한눈에.
- **스마트 복약 알림**: 설정한 시간에 푸시, '먹었어요' 한 번으로 기록. 달력에서 복약 완료율 확인.
- **가족 건강 관리**: 만 14세 미만 자녀·가족 정보를 등록하고 터치 한 번으로 계정 전환.
- **스마트 문진표**: 병원 QR을 찍으면 문진표가 병원 웹으로 제출되고 일정 시간 후 자동 파기. 병원은 웹에서 환자 문진을 관리.
- **AI 챗봇**: 질문을 분석해 DUR Tool/RAG, 제품 추천 RAG, 섭취량 RAG로 분기하는 오케스트레이션 엔진. DUR 필터링을 거친 제품만 안내하고 구어체 프롬프팅으로 답변.

## 어떻게 풀었나

- 온프레미스 서버 직접 운영. 연구실에서 지원받은 서버를 학교 내부망에서 외부로 열어야 해서 Nginx 리버스 프록시와 포트포워딩을 잡고, ZeroSSL 인증서로 HTTPS, 도메인을 서버 IP에 연결. 배포부터 장애 대응까지 직접 관리.
- 알약 이미지 인식은 YOLOv8로. AI-Hub 경구약제 데이터가 서버 용량을 넘어서, 일부만 내려받아 이전 가중치에 이어 학습하는 점진적 학습으로 풀었음. 이전 학습 이미지의 10%를 남겨 망각을 막고, 정답률 90% 이상일 때만 다음 배치로 넘어가며 미달 시 에포크·가중치 조정. 다중 알약도 바운딩 박스를 모두 찾도록 학습해 최종 정답률 92%.
- JWT 로그인 시스템과 MySQL 테이블 설계, 처방·문진 같은 민감 데이터는 AES-GCM으로 암호화해 저장.
- 식약처·심평원에 흩어진 의약품 공공데이터(e약은요, DUR 품목정보, 성분별 1일 최대투여량 등)를 하나로 합치는 데이터 파이프라인 구성. 검색은 Elasticsearch, LLM 컨텍스트는 Weaviate, 캐시는 Redis로 역할 분리.
- GPT-4o mini 복약 가이드는 근거 데이터를 먼저 조회해 프롬프트에 넣는 구조로 환각을 줄임.
